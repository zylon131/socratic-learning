# 连续带学反馈改造方案（待确认）

## 目标
学生每次提交后，老师回应刚才具体的回答，以已有学习证据决定接下来是讲解、提示、核对理由、迁移练习还是收尾。反馈自然出现在对话中，不要求学生不断点击“继续”来驱动老师，也不固定成每轮相同的表单。适用于所有学科，截图中的地理内容只是交互参考。

## 已核实的问题
- `src/subject.jsx` 的 `learningEvent` 只提交事件并刷新状态，不发起教师回复。
- `server/learning.js` 的 `applyLearningEvent` 使用出题时已生成的 explanation/hint，答对后附固定文案和“继续下一小步”按钮。答错后仍是原题和固定提示。
- `server/teacher.js` 已有根据表现调整教学的策略，但只有调用教师时才能生效；并非每次结构化作答都会触发。现有 pedagogy 元数据也不能替代学生可见的反馈。
- 自由文本会调用教师，但与选项/数值答案经过不同链路；学生输入“我选 B，同时解释……”应被作为完整请求处理，不能仅提取选项而丢弃解释需求。

## 建议改动
1. 一次提交：持久保存答案和判定依据，立即显示已收到的反馈，再自动接上一轮教师回复。选择题和数值题继续使用确定性规则判分；开放回答依据题意由老师评价，没有把握就明确待核对。
2. 教师上下文：包含当前题目、完整学生表达、规则判定、尝试次数、近期学习证据以及当前目标。无需额外创建一位评估 Agent；由同一 Harness 老师选择教学动作。
3. 学生可见反馈：针对回答说清具体对在哪里、哪里还不能确认，再给出所需解释或提示；一次答对不代表掌握。答对但自称猜测时核对理由，反复不懂时换解释或退回前置知识；要求停止时收尾。
4. 下一步由老师主动带出：可以讲一段、做比较图、给一个小问题，也可以结束；不强制每轮出题，不展示内部推理过程，不把诊断结论写成没有证据的能力标签。
5. 服务端把一次答案事件与一次自动教师回复关联，保证重试和刷新不重复调用或扣分。等待时显示“老师正在根据这次回答调整讲解”；失败时保留答案和明确失败状态，释放教师回复的预留积分，提供重试。

## 需要确认的计费变更
现有页面承诺“提交答案不消耗积分”，教师回复成功收费 2 积分。建议保持答案记录/规则判分免费，自动接续的教师回复成功仍扣 2 积分，在提交前明确显示。余额不足时仍可保存和判定答案，并明确提示老师尚未继续讲解；不伪造教师反馈、不静默跳过。

这会改变原来的免费提交操作体验，需确认后实施；本次仅修复总览默认数学的问题，尚未改动此计费和自动回复链路。

## 验收
- 跨数学、语言、人文学科验证：答对、答错、猜对、连续不懂、临时追问、主动结束。
- 选项作答后无需再次点继续；反馈引用本次回答，并按不同证据改变教学动作。
- 自由表达中同时包含答案和追问时，两者均得到回应。
- 重复点击、刷新、失败重试仅产生一次有效回复及一次扣费；失败和余额不足均有明确提示。
- 测试使用隔离账号/数据库；不向用户档案写入虚构学习或掌握度。
