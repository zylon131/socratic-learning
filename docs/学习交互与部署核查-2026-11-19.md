此次用与实际运行相同的模型配置，在独立 PGlite 数据库进行数学 4 轮、英语 2 轮的真实流式试教。六轮都完成并持久保存。首段正文约 4.2–20.4 秒，整轮约 6.2–24.9 秒。数学答错时老师指出了分数单位问题，猜对时改用角和分作类比。请老师结束时没有再出题，但把学生没有确认的理解写成“你已经明白”。英语反馈区分了时间词说明动作频率和主语导致动词变形两个问题。两科自然表达的年级都没有保存进会话阶段字段。

验收记录位于 `.local/qa/study-benchmark-20261119-1795051311545/result.json`。数据库复核确认，两次自由输入分别落到了 `math.linear_eq`（一元一次方程）和 `english.clause_parsing`（英语长难句），和实际讨论主题不符。样本只用于定位问题，不能用于推断全学科质量。

接下来依次验收三件事：

1. 老师主动给出可选起点，并让用户确认无法识别的学科或知识点。
2. 点击和文字作答共用题目与证据。用答错、猜对、答对能说明理由、选项加追问四种输入检查老师是否改变下一步。
3. 停学时只总结已确认的表现。断流或刷新时保留作答，明确标出点评状态并可恢复，记录跨学科首段反馈耗时。

## ECS

通过 Alibaba Cloud Workbench CLI 只读检查了之前指定的 ECS。Docker 可用，主机 Node.js 为 `v22.14.0`，当前代码要求 `>=24.9.0`。443 已有监听，拾光容器健康。本次看到约 733 MiB 可用内存和 27 GiB 剩余磁盘。DeepSeek HTTPS 探测返回 401，说明网络可达，模型凭据仍待单独验证。

**具备准备单实例内测的基础。** 用 Node 24 容器隔离现有服务，Linux 端按锁文件安装运行依赖。前端在本地或构建机生成 `dist`。通过受限环境文件配置模型和独立 PostgreSQL 库，应用启动时执行 schema 初始化。先走内网地址验收登录、模型流和批改，再接入口域名。

常规 HTTPS 反代目前有阻塞。在本机对同一 Host 做只读探测，HTTPS `Origin` 加 `X-Forwarded-Proto` 仍返回 403。需先用受控代理信任或明确的公开来源配置修复来源校验。反代须支持 8 MiB 请求体，关闭流式缓冲，读取超时覆盖模型的 90 秒等待，并启用安全 Cookie。公网开放前需要限制注册和模型调用频率。目前可先做受限访问的单实例内测。

未进行云端上传、启动或配置变更。云端仍待验证独立 PostgreSQL 权限、模型凭据和反代全流程。公开入口的端口范围可参考[阿里云 ECS 安全组指引](https://www.alibabacloud.com/help/en/ecs/user-guide/security-groups-for-different-use-cases)。
