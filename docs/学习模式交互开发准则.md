# 问学的老师怎样带学生学

适用于各学科标签里的首次进入、连续对话、作业讲评和下次续学。开发或评审时，先回答一个问题：**学生刚才说的哪句话或做的哪个动作，改变了老师接下来的教法？** 如果把学生换成一个给出不同理由的人，老师仍然原样讲下一段，就要重新检查这一轮。

## 从真实会话看到的三件事

2026-11-19 在龙哥指定的 Chrome 标签中观察。会话教的是学习交互设计，化学是其中的举例。以下区分历史对话与本次动手体验。

| 场景 | 页面实际发生了什么 | 问学要学会什么 |
| --- | --- | --- |
| 选 B，同时要求一步一步学三种职责的分工 | 老师先判断 B，解释这个选项抓住了什么，再补出选项里没有讲清的第三个职责。沿用上一题的例子做对照，最后给一个需要运用这一区别的新情境。 | 一条消息里可以同时有答案、理由、追问和节奏要求。处理完选择，还要兑现学生的追问。下一题应当能检验刚才解释的区别。 |
| 同一讲解中有“先补一下这个基础”和“我想继续做当前的题目” | 我点继续，组件立即改为保留原题、先自己尝试、在关键步骤给提示。切回补基础，它改问前面的数字代表几份，原来的计算题留待返回。 | 遇到卡点，说明为什么建议补、具体补什么。学生接受和拒绝应得到两种可继续的教法。此处亲手验证的是消息内的互动演示，页面中的后台说明不能证明 ChatGPT 真有对应的数据库记录。 |
| 学生用自己的比喻解释了思路，又要求加快进度 | 老师接住了比喻，把它用于解释任务恢复，并在同一轮改为按架构层级集中讲解。后续学生要求正式方案，老师给出可阅读的成果。 | 学生可以改变这一节课的目标、深度、节奏和交付形式。验收时看下一段实际讲了什么，光说“好的，我们加快”不算。 |

另一个来自龙哥早先截图的观察是，面对“帮我学习某学科”这样宽泛的请求，老师先介绍怎么学、这门课有哪些方向，再给一个容易回答的阶段选择。新用户即便还无法描述弱点，也能迈出第一步。

## 一轮教学怎么做

1. **进学科就有起点。** 已知学段且没指定专题时，先给这一阶段的几个相关入口和一个可直接开始的默认入口。已知学到哪个专题时，直接进入那个专题。已有题目或从错题本进入时，直接接住那道题。已有同科记录时，从上次未完成处接。学习范围、学校进度和已验证的能力分别记录，总体看板只汇总真实记录。
2. **先回应学生这一句。** 能判对错的先给判断。计算结果正确且当前目标已达成时，简短反馈后推进当前目标。过程是本题目标、答案暴露了具体误区，或学生自述猜测时，才针对关键步骤追问。开放题可以先复述学生的依据，再请他补一条证据。肯定要落在具体表现上。
3. **根据学生意图安排下一步。** 已能说明理由，可以换情境验证；理由矛盾，就把两个说法摆在一起；学生仍不明白，就换例子、图或操作；学生要求全貌，就集中讲清。连续选对是辨认的证据，也是该换一种教学动作的信号。学生请求续讲且理解依据有待验证时，老师可以把解释、对比和有效的小问题组织在同一轮。独立解释和独立应用分别取证。学生说今天先停，就收在真实进展和下次接点。见 [教学决策专项审计](教学决策专项审计.md)。
4. **交互放在需要它的那句话旁边。** 阶段选择、诊断题适合点选；解释理由、追问和纠正老师应支持自由输入。图用来呈现难以从文字看出的关系，表用来对照容易混淆的概念。探索时立即显示操作后果；提交时再留下本次作答。模型仍在生成时，可以先显示已收到和可确定的结果，生成失败要显示哪条点评待恢复。
5. **把学到了什么说准确。** 原题选对、在提示下纠正、能解释理由、换题后独立运用，是不同表现。程序核对有明确答案的部分，模型解释开放表达、提出下一步教法，由服务端根据具体题目和学生证据更新进度。老师讲过的内容、学生点过的选项、学生要求“快一点”，各自有不同含义。未确认的知识点保留待确认状态。

## 用同一道题验收不同教法

以下是评测输入，只用于隔离测试。每个分支从同一题面独立开始。数学可以问“等大的两张纸，一张的二分之一和另一张的四分之一，哪块大？”。

| 学生的动作或原话 | 必须观察到的反馈 | 核对的学习记录 |
| --- | --- | --- |
| 第一次点击数学，打不出具体需求 | 老师给一个可立即回应的起点；学生可以点，也可以说想学别的 | 初次进入不产生掌握记录；英语的阶段独立 |
| “四分之一大，因为 4 比 2 大” | 点出学生比较了分母；用同样大的纸展示分得越多，每份如何变化，再让学生判断 | 留下原理由；误区作为待验证判断 |
| “二分之一，我猜的” | 承认这次选对，请学生对照纸条，或用自己的话说明依据 | 作答正确，独立理解待验证 |
| “二分之一，因为同一张纸平分两份，每份更大。换成不同大的纸呢？” | 认可理由；回应“整体大小”这个追问，用不同大小的纸解释原结论的适用条件 | 保留原题理由；新问题单独记录 |
| “能快点吗？先把比较分数的方法一起讲清” | 当轮改成集中讲解，给适用条件与例子，学生可主动回到练习 | 节奏变更不增加掌握度 |
| 作业讲评中选择补基础，随后返回；再从相同起点选择继续原题 | 前一条路径能回到同一道题、同一步；后一条路径在原题给最小提示 | 两条路径均保留原作答，补学和提示留有出处 |
| “今天先到这里”，刷新后再进数学 | 收束已确认的表现和一个待验证点，重新进入时从该点接起 | 总览与学科记录相符；重复打开不重复记证据 |

再用一门非数学学科复测。例如英语学生写下“He walk to school every day”，先请他找主语，再听他解释为什么要用 walks。如果学生已经说清动作频率，却仍不会按主语选动词，下一步专门处理动词形式。验收人员逐轮对照学生原话、老师反馈、下一步任务和已保存的能力证据；只看页面是否渲染成功，无法判断教学质量。

## 2026-11-19 同题实测与改造方案

在独立的本地 PGlite 库中，用两个新账号经正常学习 API 提交相同题意。每个账号完成出题和作答两轮。以下结论来自真实模型回复、重读会话、进度接口和数据库。

| 输入 | 老师当轮反馈 | 学习记录 | 结果 |
| --- | --- | --- | --- |
| 二分之一大，我猜的 | 确认选对，用平分纸片解释，再换成相同大小的纸比较三分之一和六分之一，让学生说明理由 | 证据写的是老师选择追问理由，归入一元一次方程；分数比较在进度中仍是未观察 | 教学反馈通过，证据归属失败 |
| 二分之一大，给出等面积下的理由，再追问整体不同时怎么比 | 确认理由，讲清整体大小的影响，再给长短不同的纸条练习 | 正确理由没有形成学习证据；新练习是正文里的 A/B/C，正确项还写出了算式结果 | 承接追问通过，证据与练习呈现失败 |

两次作答的首段正文分别在约 6.6 秒和 7.9 秒到达。两组四轮都完成并能重读。首题是用户明确提供的题目，本次未覆盖新用户进入学科时的主动引导，也没有覆盖点击题卡、英语或断线。验证记录见 [同题对照结果](../.local/qa/same-question-20261119-1795052981773/result.json)。

**设计目标。** 拿同一道题把学生作答、理由、追问、老师反馈和能力记录连起来。一次答对可记事实；明确说猜的，理解仍待检查；理由成立，记录它能够证明的范围；换题还没有回答时，独立迁移仍待验证。

1. **先把题和知识点绑定。** 复用现有题卡、任务和知识点 ID。目录点选沿用其 ID，自由学习优先使用当前已确认的题目或知识点。只有明确匹配才给具体知识点记进度；暂时无法确认时保留原话和会话上下文，等确认后再归档。检查数学、英语及其他学科的固定默认点，避免它们提前成为能力证据的归属。
2. **把本轮看到的事实和下一步教法分别写入。** 题卡提交与当前题下的文字作答共用题目标识。证据附学生原话、题目和是否借助提示。规则负责可客观核对的答案，语义评估负责判断理由及其局限。老师可以同时指出答题表现并回答新问题。服务端核验证据来源后更新进度，避免因决定追问就写入一条能力证据。
3. **将这一轮决定落实到反馈和练习。** 猜对先帮学生说清理由，能解释并提出新条件就顺着问题讲，再用新例子检验。确认选择后可以马上给客观结果，老师随后补讲。需要学生判断的题卡把答案留到提交后。更新现有教师策略中限制为纯文字、每轮都要出题的要求。

实现复用 [教学编排](../server/orchestrator.js)、[知识点识别](../server/skills-registry.js) 和 [证据写入](../server/evidence.js)。题卡保存题号和已匹配的知识点，文字作答关联当前题号，理由须引用学生本轮原文。明确的选项和数值可以程序核对，开放作答按语义评估保存。模型决定追问这一动作本身不会写成能力证据。缺少明确归属的作答记入会话，显示知识点待确认。启动时给旧库增加可选证据字段，已有聊天继续可读。

**实施后复测。** 数学、英语各两个独立账号完成同题对照。猜对均保留正确选项事实和猜测标记，技能状态为待验证。能说明理由的回答保留原文，正确归入分数大小比较及一般现在时的主谓一致。两个追问都获得当轮解释，接着给出有新题号的题卡。英语实际提交题卡后，规则结果立即可见，老师接上点评。使用同一请求号重发以及刷新回读，没有多写证据。见 [四条文字分支及题卡记录](../.local/qa/evidence-linked-20261119-1795058333215/result.json) 和 [学科开场与题卡点评](../.local/qa/opening-card-20261119-1795058505183/result.json)。

英语补测完成了第三轮。学生自行答对复数主语的题并解释理由，数据库里的新题证据关联回原题。学生同时要求结束，老师总结了已展示的两条理由，留出待学内容，回读后没有待答新题。这条样本证明新情境的作答可追溯，技能状态仍是已理解。见 [英语迁移与收尾](../.local/qa/transfer-20261119-1795058631867/result.json)。

本轮覆盖明确题面与两门学科。历史误归类记录、其他学科的自由题目以及知识点尚待确认时的后续归档仍需复核。

## 当前优先顺序

根据[问学本地真实试教与部署核查](学习交互与部署核查-2026-11-19.md)，首先验证学科入口能主动起步、主题识别准确。其次让点选和自由回答共同指向当前题，并让“猜对”和“能解释”得到不同反馈。最后验证收尾、刷新、补学返回时，老师的话、原题与看板记录三者一致。以上是开发验收目标，完成状态以项目试教记录为准。

## 高一数学首轮复盘与修订方案

在 4194 的实际浏览器会话中，学生明确请求“帮我学习高一数学”。老师先给出 `2(x − 3) = x + 1`，同时询问学校讲到哪个章节。页面仍显示“学段：自适应”。学生在只接收数值的题卡填入正确答案 7，系统和老师各确认一次，随后老师继续追问如何去括号。这一路径在确定高一课程起点之前就要求学生做题并解释步骤。正确答案只提供了这道题的结果证据。

当前的 [学科开场和作答接续](../server/learning.js) 将低门槛诊断题作为开场默认动作，答对后缺少理由也容易触发追问。[教学编排](../server/orchestrator.js) 提供单独的学段字段，本轮没有把自然语言里的“高一数学”设为当前课程范围。上一轮评测直接指定了题面，绕过了这个入科环节。

**改动方案待确认**

1. **先用已知信息选入口。** 从当前学科里的明确学段、专题、继续学习记录确定课程范围。学生说“学高一数学”时，先按高一列几个可点击的章节，例如集合与逻辑、不等式、函数，再提供“还没开始，带我入门”。可以附一个简短的学段内例子，让学生马上开始。拿不准教材顺序时，请学生选正在学的章节，允许跳过。当前会话的学习范围与能力档案分开。
2. **把带学和摸底按学生意图处理。** “帮我学”直接进内容。“帮我看看基础在哪”才进入诊断。诊断聚焦本次目标所需的几个相关能力，可以把两三道短题集中呈现，允许跳过。结果说明本次观察到什么、还有什么没测。识别不到当前知识点时，给学段内入口或请学生确认。只有当前学习已经暴露出具体障碍时，才建议回补相关先修。
3. **降低答对后的摩擦。** 普通计算题只要求结果时，自动反馈后进入下一小步。若需要看思路，从一开始就使用允许写关键步骤的题型，并说明想看什么。对猜对、重复出错或当前目标确实是理解推理过程的回答，做一次有针对性的追问。
4. **点选可以直接发出完整的学习意图。** 截图中点 B 后，聊天里出现了选项字母、选项内容和请老师继续讲解的请求，老师随即回应。问学已有题卡自动接续，当前界面显示简短作答，后续由隐藏指令启动点评。调整为点选后立即回显一条完整消息，例如“我选 B（区间内随自变量增大而增大）。请判断并接着讲。” 使用题号、选项和可选的学生原话保存作答与续讲意图。选章节可以直接发“从集合开始，请带我入门”。能客观判对错就先给简短反馈，老师随后解释并推进。允许学生改用文字补理由或带上追问。默认续讲请求代表按钮的交互意图，不能当作学生给出的理解证据。

验收从空档案进学科开始。发送“帮我学习高一数学”，首轮能选高一范围内的章节，点一下进入教学。发送“函数已经讲到单调性”，老师直接从单调性开始。交对一道普通计算题，老师简短反馈并推进。两道不同题都点 B 时，各自回显本题的选项内容并继续讲，刷新后可回读，同一次提交只记录一条证据。另用初中英语复测自报学段、明确专题和主动要求摸底的三种路径，检查已证实的知识点与课程范围分别记录。避免用几道快速题给学生贴整科水平标签。
